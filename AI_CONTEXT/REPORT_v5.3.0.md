## 1. ملخص تنفيذي

اكتملت مرحلتان رئيسيتان في هذا التحديث. الأولى هي **استكمال نظام المصادقة المتكامل** (الهاتف + البريد الإلكتروني + اسم المستخدم) الذي بدأ في الإصدار v5.2.0، حيث جرى تصحيح مشكلة قاعدة البيانات داخل صورة Docker وإعادة بنائها بنجاح، ثم رفع الإصدار إلى GitHub. والثانية هي **تطوير نظام Offline-First كامل لتطبيق Flutter** باستخدام مكتبة Drift وSQLite، يشمل قاعدة بيانات محلية، طابور عمليات للمزامنة (Outbox)، محرك مزامنة تدريجي، تخزين الوسائط محليًا، وكاشف حالة الشبكة، وذلك دون أي تعديل على JWT أو FCM أو WebRTC أو أي جزء يعمل حاليًا.

تم البناء والاختبار بنجاح: تحليل الكود (flutter analyze) نظيف تمامًا، وصورة Docker مبنية وتعمل، وتطبيق APK جاهز للتثبيت.

## 2. الإصدار v5.2.0 — استكمال المصادقة (تصحيح Docker)

كانت صورة Docker السابقة تفشل في التحقق من OTP البريدي (خطأ 500) لأن جدولين جديدين (`user_subscriptions` و`device_registrations`) لم يكونا ضمن schema.sql الأصلي. جرى الحل بجعل ملف الهجرة `database/migrate_auth.sql` مقاومًا للتكرار (idempotent) عبر تحويل أوامر `ALTER TABLE` إلى أوامر شرطية تتحقق من وجود العمود قبل إضافته، ثم إعادة بناء الصورة وتشغيل اختبار دورة كاملة داخل الحاوية الجديدة:

| الخطوة | النتيجة |
| --- | --- |
| POST /auth/register-email | 200 — حساب بريد يُنشأ وOTP يُرسل |
| POST /auth/verify-email-otp | 200 — JWT + بيانات المستخدم |
| POST /auth/set-password | 200 — كلمة مرور تُضبط |
| POST /auth/login-email | 200 — دخول ناجح بالبريد وكلمة المرور |
| POST /auth/login-username | 200 — دخول ناجح باسم المستخدم |
| إيقاف إعداد التسجيل من الإدارة ثم محاولة التسجيل | مرفوض من الـ Backend (فرض الإعدادات يعمل) |

الوصلة: https://github.com/alghazaliye/nova/releases/tag/v5.2.0

## 3. الإصدار v5.3.0 — نظام Offline-First (Drift + SQLite)

### 3.1 المكوّنات الجديدة (lib/offline/)

| الملف | الوظيفة |
| --- | --- |
| `local_nova_db.dart` | مخطط قاعدة البيانات المحلية عبر Drift: المحادثات، الرسائل، المستخدمون، الوسائط، طابور العمليات، حالة المزامنة |
| `local_nova_db_provider.dart` | تهيئة قاعدة SQLite على الجهاز عبر sqflite_common_ffi |
| `local_sync_service.dart` | الكتابة من بيانات الخادم إلى القاعدة المحلية مع حماية التعارضات (لا يُستبدل أي رسالة محلية قيد المزامنة) |
| `outbox_service.dart` | طابور العمليات: الرسائل المعدلة أو المرسلة أثناء الانقطاع تُخزن وتُعاد المحاولة بتأخير متصاعد حتى عودة الاتصال |
| `sync_engine.dart` | مزامنة تدريجية من الخادم بمؤشر تقدم |
| `network_detector.dart` | ثلاث حالات: متصل / الخادم غير متاح / بدون إنترنت، مع فحص دوري كل 30 ثانية ونقطة /health |
| `media_store.dart` | تنزيل الوسائط محليًا حسب الفئة + تنظيف الكاش وحساب الحجم المستخدم |

### 3.2 السلوك الفعلي في التطبيق

عند فتح التطبيق يتم تشغيل مراقب الشبكة وطابور المزامنة تلقائيًا من `main.dart`. في شاشة المحادثات، بعد جلب المحادثات من الخادم تُحفظ نسخة محلية؛ فإذا انقطع الاتصال تُعرض آخر نسخة محلية تلقائيًا ولا تظهر الشاشة فارغة. وفي شاشة المحادثة، عند إرسال رسالة نصية تُحفظ محليًا فورًا بحالة "جارٍ الإرسال" قبل محاولة الشبكة؛ فإذا فشل الإرسال تُضاف إلى طابور العمليات وتُرسَل تلقائيًا عند عودة الاتصال دون أي تدخل من المستخدم. كما أُضيف إلى صفحة الإعدادات قسم جديد "التخزين والبيانات المحلية" يعرض حالة الاتصال الحالية وحجم التخزين المستخدم مع زر مسح الكاش.

### 3.3 شاشة الدخول الديناميكية

أصبحت شاشة الدخول تستجيب لإعدادات الإدارة عبر `GET /auth/config`: إذا كانت طرق التسجيل والهاتف والبريد مفعّلة تظهر تبويبان، وإذا كانت طريقة واحدة فقط مفعّلة يظهر حقل واحد فقط، وإذا أوقفت الإدارة كل الطرق تظهر رسالة "التسجيل متوقف". أُضيفت دوال كاملة في `auth_provider.dart` للتسجيل والتحقق بالبريد والدخول بالبريد واسم المستخدم وتغيير كلمة المرور.

### 3.4 ما لم يُمس

JWT ومصادقة التوكن كما هي، وإشعارات FCM كما هي، وبنية WebRTC والـ signaling كما هي، والمحادثةات والمجموعات والقصص والمكالمات الحالية دون أي تغيير وظيفي — النظام الجديد يعمل بالتوازي فوق الطبقة الحالية.

## 4. حالة النشر الخارجي

النشر على Render.com ما زال متوقفًا بسبب تعذر تجاوز hCaptcha في صفحة التسجيل (يتطلب تدخّلًا يدويًا من مالك البريد). عند رغبتك في استئنافه، أنصح بتسجيل الحساب بنفسك عبر GitHub OAuth لتجاوز التحقق، أو العودة إلى الصفحة عند توفر وقت للتدخل اليدوي.
